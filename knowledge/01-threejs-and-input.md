# このプロジェクトで出てくる見慣れない道具

コードを読むときに「これは何をしているのか」で止まりやすいところを、
先回りして書いておく。**ここに書いてあるものは、信頼して素通りしてよい部分**でもある。

## Three.js まわり

### `ShaderMaterial` と GLSL

海と空は、既製のマテリアルではなく自分で書いた小さなプログラム（シェーダ）で
描いている。GPU の上で「頂点をどこへ動かすか」（vertex shader）と
「この画素を何色にするか」（fragment shader）を決めるもの。

海が波打って見えるのは、平らな板の頂点を `sin` の合成で上下させているだけで、
水の物理計算はしていない。

**`#include <colorspace_fragment>` は必ず要る。** three は色を linear-sRGB という
中間形式で持っていて、既製のマテリアルは描画の最後に sRGB へ戻している。
自前シェーダはその工程を持たないので、入れないと指定した色より暗く沈む。
（M0 のレビューで指摘されて直した箇所）

### `InstancedMesh`

同じ形のものを大量に描くとき、1 個ずつ Mesh にすると描画命令（ドローコール）が
その数だけ増えてスマホが落ちる。`InstancedMesh` は「同じ形を、位置と色だけ変えて
N 個」を 1 回の命令で描く仕組み。弾に使っている。

位置・向き・大きさは 4x4 の行列で与える。毎フレーム `new` しないよう、
使い捨ての `Object3D`（`dummy`）を 1 つ使い回して行列を作っている。

### `dispose()`

GPU 上のメモリは JavaScript のガベージコレクタでは解放されない。
`geometry.dispose()` / `material.dispose()` を明示的に呼ぶ必要がある。
このプロジェクトでは、作った層が捨てる責任も持つ（`createEnemyModelFactory` が
`dispose` を返しているのはそのため）。

### オイラー角の順序 `'YXZ'`

`camera.rotation.set(pitch, yaw, bank, 'YXZ')` の最後の引数。
「まず左右に振り、次に上下に振り、最後に傾ける」という順序の指定で、
一人称視点の標準的な選び方。既定の `'XYZ'` だと、上を向いた状態で左右に振ったときに
視界が捩れる。

## 端末のセンサー

### `DeviceOrientationEvent` の beta / gamma

- `beta`: 端末の前後の傾き。水平（画面が上向き）で 0、垂直に立てると 90
- `gamma`: 端末の左右の傾き。右へ倒すと +

**この 2 つは端末の軸で測られていて、画面がどちら向きかを知らない。**
横持ちにすると前後と左右が入れ替わるので、`screen.orientation.angle` のぶんだけ
回して「プレイヤーから見た上下左右」に直している（`src/input/tilt-math.ts`）。

この変換は実機がないと確かめようがないので、0/90/180/270 の 4 姿勢について
符号をテストで固定してある。

### iOS の許可

iOS 13 以降、傾きセンサーは `DeviceOrientationEvent.requestPermission()` で
本人の許可を取らないと使えない。しかも**ユーザーのタップから直接始まった呼び出し**
でないと、問答無用で拒否される。

開始画面を挟んでいるのは演出のためではなく、この「押してもらうボタン」が
どうしても要るから。

## 設計の言葉

### 「純関数」

同じ入力からは必ず同じ出力が出て、外の世界を書き換えない関数のこと。
`stepWorld` と `stepFlight` と `calculateScore` がそれで、だから
「ブラウザを立ち上げずに」テストできる。

`stepWorld` の中で敵の HP を減らしているように見える箇所があるが、
あれはそのフレームで作った複製に対してで、渡された world は無傷のまま返る。
（`JSON.stringify` で前後を比べるテストがそれを保証している）

### 「依存性逆転」

`game/` は「照準がどこを向いているか」だけを知っていて、それが傾きセンサー由来か
指のドラッグ由来かを知らない。逆に `input/` は可動範囲（何度まで振れるか）を知らない。

こうしておくと、「傾けられない時にスワイプで同等」という要件が、
両者の合流点 1 箇所だけで守られる。片方を直したらもう片方も直す、という状態にならない。

### 「プール」

毎フレーム作って捨てると、ガベージコレクタが動いた瞬間に画面が引っかかる。
あらかじめ必要数を作っておいて、使わないものは隠すだけにする方式。
敵機・爆発・破片がこれ。

## テストが守っているもの

テストは「コードが動くこと」ではなく**企画が壊れていないこと**を見ている。

- 当て続ければ落とせる／横を向いていれば当たらない
- 貫通弾は複数機を貫くが、同じ機体には二度当たらない
- HP が尽きたら世界が止まる（リザルトの裏で時間が進まない）
- 速く終えるほど点が高い／負けても撃墜と命中率は残る
- フレームレートが変わっても手応えが変わらない

CI で落ちたときは、書き方ではなく**遊びの規則が変わってしまった**と読んでよい。
